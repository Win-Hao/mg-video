# 技术栈参考

这套流程是：网页里按时间画出一帧 → 无头浏览器截图 → 拼成 MP4（`tools/render.mjs`）。所以画面用的技术都得能在浏览器里跑；Python 只用来合成配乐，或者像 Manim 那样自己出视频。

## 想呈现什么，用什么

| 想呈现的 | 用什么 | 为什么 | code-video 测试时跑通的例子 |
|---|---|---|---|
| 像素画、老游戏 | Canvas 2D | 小画布画完整数倍放大、关掉平滑，就是一格格的像素 | `02-像素` |
| 老电视、胶片、发光、色差这类质感 | WebGL2 片元着色器 | 把画好的画面当纹理逐像素加效果，内容不动 | `03-复古街机` |
| 界面、卡片、文字排版、信息图、时间线 | HTML + CSS + SVG | 排版、字体、圆角、阴影最省事 | `06-界面动效`、`07-简史` |
| 矢量插画、图标、描线、形状变形 | SVG | 路径能一笔笔描出来，也能变形 | |
| 手绘、水彩、彩铅、蜡笔 | p5.js + p5.brush | 现成的笔刷和纸纹 | `04-手绘` |
| 3D 场景、物体、镜头运动、空间结构 | Three.js | 浏览器里最成熟的 3D 库 | `05-3D` |
| 粒子、大量小元素 | Canvas 2D（几千个以内），更多用 Three.js 的 Points | | `01-一句话` |
| 数据图表、数字滚动 | D3.js 或手写 SVG | 比例尺、坐标轴、形状现成 | |
| 地图、路线 | D3（d3-geo）+ GeoJSON / TopoJSON | 投影、路径现成 | |
| 数学公式 | KaTeX 排公式，CSS / SVG 做变形；要一步步推导的那种动画用 Manim | KaTeX 在网页里排版快；Manim 专门做公式推导 | |
| 掉落、碰撞、弹跳（2D 物理） | Matter.js，固定步长 | | |
| 配乐、音效 | Python + numpy 合成 | 不用找音乐文件，节拍和画面用同一张表 | `01`、`06`、`07` |

一条片子里可以混着用：Three.js 画 3D，上面叠 HTML 标注；Canvas 画完再进着色器加质感。

## 每种怎么接

**通用**：库装在成品文件夹里（`npm i three`），页面里用相对路径 `./node_modules/…` 引；页面暴露 `window.render(t)` 画第 t 秒，准备好设 `window.__ready = true`。画面只由 t 决定：不用 requestAnimationFrame、CSS 动画和过渡、setTimeout、Date.now、Math.random（随机数用带种子的）。

- **Canvas 2D（像素）**：小画布画，尺寸要能整除成片（1920×1080 用 192×108，放大 10 倍；640×360 用 160×90，放大 4 倍），大画布设 `imageSmoothingEnabled = false` 再 `drawImage` 整数倍放大；所有坐标取整
- **WebGL 着色器**：`getContext('webgl2', { preserveDrawingBuffer: true })`，不加 `preserveDrawingBuffer` 截出来是黑的；每帧把画好的 canvas 用 `texImage2D` 传成纹理，画一个铺满的四边形；时间用 uniform 传进去
- **HTML / CSS / SVG**：位置、大小、透明度都在 `render(t)` 里算出来直接设；字体用 `@font-face` 引本地文件，`document.fonts.ready` 之后再设 `__ready`
- **p5.js + p5.brush**：`<script src="node_modules/p5/lib/p5.min.js">` 加 `<script src="node_modules/p5.brush/dist/p5.brush.js">`；`createCanvas(W, H, WEBGL)`（p5.brush 要 WEBGL 模式）、`noLoop()`，`render` 里调 `redraw()`；每张画之前 `randomSeed(固定数 + 第几张)`，线条的抖动才不会每次渲都不一样；一秒只换 12 张时，`render(t)` 返回第几张当 key，同一张不重复截图
- **Three.js**：页面用 `<script type="module">`，`import * as THREE from './node_modules/three/build/three.module.js'`；`new THREE.WebGLRenderer({ antialias: true, preserveDrawingBuffer: true })`；`render(t)` 里按 t 摆好相机和物体，再 `renderer.render(scene, camera)`，不用 `THREE.Clock`、`setAnimationLoop`。要用 `three/examples/jsm/` 里的东西（后期、控制器、加载器），页面加一个 importmap 把 `"three"` 指到 `./node_modules/three/build/three.module.js`
- **D3**：`<script src="node_modules/d3/dist/d3.min.js">`；只用它的比例尺、形状、地理投影，不用 `d3.transition`（它靠计时器，截图对不上）
- **地图**：世界地图数据可以用 `world-atlas`（`node_modules/world-atlas/countries-110m.json`），配 `topojson-client` 转成 GeoJSON。**画到中国国界、领土的地图，用审过的标准地图，别自己拼边界数据**：在国内公开发布地图要过地图审核，边界画错是硬伤
- **KaTeX**：引 `node_modules/katex/dist/katex.min.js` 和 `katex.min.css`，`katex.render(公式, 元素)`；动画还是在 `render(t)` 里改 transform 和透明度
- **Manim**：`pip install manim`（排公式还要装 LaTeX）。它自己渲出 MP4，不走 `render.mjs`；分辨率、帧率在命令行参数里指定（看 `manim render --help`）；要配乐就用 ffmpeg 把音频合进去
- **Matter.js**：`node_modules/matter-js/build/matter.min.js`；固定步长（比如 1/60 秒），`render(t)` 里从头模拟到 t（或者第一次把每一步都存下来），同样的初始条件每次结果才一样
- **配乐**：见 `references/audio.md`；默认用 mgsound 自带的配乐（风格卡的 Sound 一行选哪种）；也可以自带一条配乐：`cues.json` 里设 `"bed": null`，按片子的 BPM 渲染或找一条 48 kHz 的 WAV，在 `audio.py` 里用 `soundfile` 读进来，`m.add(Sound(x.T), at=0, bus='music')`

## 拿不准用哪个

先想观众要看懂的是什么关系：先后顺序 → 时间线（HTML / SVG）；空间位置、结构 → 3D；数量对比 → 图表；推导 → 公式动画；氛围、情绪 → 插画、手绘。把挑的理由写进 `<style>` 那块（「空间关系用 3D，因为……」），它照着做，也方便用户改。

## 其他可选的（code-video 测试时没实测过，第一次用先跑个几秒的小样）

**网页里能直接接的**（照样走 `render.mjs`，关键是能「跳到第 t 秒」）：

| 技术 | 擅长 | 怎么接 |
|---|---|---|
| GSAP | 复杂的出场编排：一堆东西按顺序、错开、带缓动出来 | 建好时间线先 `pause()`，`render(t)` 里 `tl.seek(t)` |
| PixiJS | 2D 大量精灵、粒子、滤镜，比 Canvas 2D 快 | 停掉它自带的 ticker，`render(t)` 里摆好再手动 `app.renderer.render(app.stage)`；画布开 `preserveDrawingBuffer` |
| Lottie（lottie-web） | 直接放设计师做好的 After Effects 动画 | `anim.goToAndStop(帧号, true)` |
| anime.js、Motion | 轻量的补间动画 | 只用能 seek 的接口，或者把进度自己算出来 |
| Theatre.js | 给 Three.js、DOM 动画打关键帧的可视化编辑器 | `sheet.sequence.position = t` |
| Babylon.js、react-three-fiber | Three.js 之外的 3D 选择 | 一样要关掉自带的动画循环，按 t 摆好再渲 |
| WebGPU | 大规模粒子、流体模拟 | 浏览器要支持 WebGPU；能用 WebGL 做的先用 WebGL |
| Tone.js | 在网页里写音乐：合成器、鼓机、和弦 | `Tone.Offline` 离线渲成 WAV，替代 numpy 合成 |

**自带渲染器的整套框架**（自己出视频，不走 `render.mjs`）：

| 技术 | 擅长 | 注意 |
|---|---|---|
| HyperFrames | 做口播成片常用：HTML + GSAP 时间线，能叠视频素材、配乐、字幕 | 多场景、要叠真实视频素材时比 `render.mjs` 省事；用法看 HyperFrames 的文档 |
| Remotion | 用 React 写视频，组件化，配乐字幕都有 | 公司用要看它的授权条款（个人和小团队免费，规模大了要买） |
| Motion Canvas / Revideo | 用 TypeScript 一步步写讲解动画，适合知识讲解 | 自带编辑器和渲染 |
| Manim | 数学推导 | 见上文 |

**网页外的**：

| 技术 | 擅长 | 要装什么 |
|---|---|---|
| Blender（Python 脚本） | 真实材质、光影、物理的 3D，比 Three.js 真得多，也慢得多 | **要先装 Blender 软件**（免费，几百 MB）；装好后不用开界面，命令行后台跑脚本出画面。也有 pip 装的 `bpy`，但对 Python 版本有要求、包很大 |
| Matplotlib / Plotly 动画 | 数据图表动画，Python 直接出视频 | pip 装；出 MP4 要 ffmpeg |
| MoviePy、FFmpeg 滤镜 | 拼接、剪辑、叠字、转场，用来把画好的片段合成，不用来画 | pip 装 MoviePy；FFmpeg 用系统包管理器装（`brew install ffmpeg`） |

**3D 用 Three.js 还是 Blender**：Three.js 是实时渲染（游戏引擎的路子），一帧几毫秒，偏风格化，低多边形、镜头运动、和网页排版混用都方便，默认用它。Blender 的 Cycles 是光线追踪，柔和阴影、光的反弹、玻璃折射、水面倒影、景深都是真算出来的，还有布料、流体、烟雾这些物理模拟，接近 CG 电影和产品渲染图；代价是一帧几秒到几分钟（自带的 Eevee 快很多，效果介于两者之间）。用户要写实质感（产品展示、玻璃水面、写实场景）才挑 Blender。用法：`blender -b -P 场景.py`，`-b` 是不开界面在后台跑，脚本里建模型、上材质、打光、摆相机、设关键帧、渲染；顺手存一份 `.blend`，用户想看场景、手动调，再打开界面。

**要装新东西时**：npm、pip 装进成品文件夹的小库直接装；Blender、LaTeX 这类大软件，或者要动系统环境的，先跟用户说要装什么、多大、为什么，用户同意再装。

挑的时候先看前面那张主表：测试时跑通的优先；主表没有的需求再来这里找，挑了的话在 `<style>` 里写清用什么、为什么。
